# Technical Design (v0.2.0)

Status: living document. Evaluations below are desk evaluations from ecosystem knowledge as of mid-2026.
No comparative benchmarks have been run yet. Each choice marked "re-verify" must be benchmarked when its
subsystem is first built (rule 7 of the brief).

Rule check: every dependency must be pure Rust. `cargo tree -i cc`, `-i cmake`, `-i bindgen` must report
nothing for the Windows target. Licenses are listed with `cargo tree --format "{p} {l}"`.

Debug builds: the workspace `Cargo.toml` sets `[profile.dev.package."*"] opt-level = 2`, so the dependencies (manifold
booleans, parry, faer) are optimized in debug builds while the workspace crates still compile fast. The `cad-mech` tests
with modelled threads went from 51 s to 3.7 s and `tests/mcp_phase5e.sh` passes in about 85 s.

## 2. Crates and dependency direction

```
cad-app ──► cad-document ──► cad-constraints ──► cad-geometry ──► glam
                  ├──► cad-params
                  └──► cad-modeler ──► cad-topology, cad-geometry, manifold-rust, earcutr
                  └──► cad-arch ──► cad-modeler, cad-geometry
                  └──► cad-mech ──► cad-modeler, cad-geometry, parry3d-f64
                  └──► cad-analysis ──► cad-modeler, glam
   │
   └──────► cad-renderer ──► wgpu
```

- `cad-geometry`: shapes, tolerance, validation, tessellation, picking math. No UI, no GPU.
- `cad-document`: entities, commands, undo/redo history, native file format.
- `cad-arch` (Phase 4): wall joins, plan outlines with opening gaps, wall solids with opening cuts, door and window symbols, room areas, floor slab, roof and stair solids, IFC classes on a level. Works on shapes, not on the document; `cad-document` (rebuild) and `cad-app` (plan drawing) depend on it.
- `cad-mech` (Phase 5): part generators (involute spur gear, stepped shaft, helical spring, ISO 4017 screw, ISO 4032 nut with cosmetic or modelled threads, ISO 15 deep groove ball bearing) as solids from evaluated parameters, their designations and threads. Works on numbers, not on the document; `cad-document` (part features) depends on it. It also holds the material density table for BOM masses; joint frame math (batch C) and the interference and clearance check (batch D) live here too. BOM rows are built in `cad-document`, because they read feature names and component metadata.
- `cad-analysis` (Phase 6): accuracy labels and mass properties of meshes (batch A); later kinematics helpers, the tetrahedral mesher and the FEA solver. Works on meshes and numbers, not on the document; `cad-document` builds the reports.
- `cad-renderer`: wgpu pipelines and WGSL. Knows only vertices and matrices; it does not depend on the kernel.
- `cad-app`: egui UI, cameras, tools, viewports.
- `cad-import-export` (added in Phase 2): `to_svg` and `to_dxf`. Depends on `cad-document` and `cad-geometry`;
  `cad-app` depends on it. The `dxf` and `roxmltree` crates are test-only dependencies used to read the output back.

The brief lists 23 crates. A crate is created when its first real code exists; empty crates are not created.
Planned splits: `cad-topology` and `cad-modeler` (Phase 3), `cad-constraints` and `cad-drafting` (Phase 2),
`cad-arch` (Phase 4, built), `cad-mech` (Phase 5, built), `cad-analysis` (Phase 6, built),
`cad-import-export` and `cad-plugin-api` (Phase 7).

## 3. Geometry representation

- Model units are millimetres. Coordinates are `f64`. The GPU receives `f32`.
- Phase 1 shapes are analytic and parametric: `Line`, `Circle`, `Rect` (2D, on the XY plane) and `Box`,
  `Cylinder`, `Sphere` (3D). Each shape validates itself against a `Tolerance`. Invalid geometry is rejected
  with an error and never stored.
- Display geometry is derived: `tessellate()` gives triangles, `outline()` gives edge segments.
- Phase 3 adds B-Rep: geometry (curves, surfaces) and topology (vertex, edge, wire, face, shell, solid) in
  separate modules, joined by handles. Analytic shapes then become features that produce B-Rep bodies.

## 4. Document architecture

- A `Document` owns entities in an ordered map keyed by a stable `EntityId`.
- Every change is a `Command` (`Add`, `Remove`, `SetShape`). `Document::apply` validates, mutates and returns
  the inverse command. `History` stores inverse transactions, so undo and redo cost O(change), not O(document).
- A transaction is atomic: if one command fails, the applied ones are rolled back.
- `revision` counts changes. The app uses it for the unsaved-changes flag and to upload GPU buffers only when
  the scene changed.
- Native format `.cadproj`: JSON with a `version` field. Loading rejects newer versions and re-validates every
  shape. Saving writes a temporary file and renames it, so a crash cannot truncate a project.
- Phase 3 adds the feature dependency graph on top of the same command and history mechanism.

### Phase 2 additions
- Layers live in the document (`Layer`: name, colour, visible, locked). Layer 0 always exists. Entities carry a
  `LayerId`. Layer edits are commands, so they undo and mark the project dirty. Hidden layers are not drawn or
  picked; locked layers are drawn but not picked.
- `History::execute_merged` folds a run of "set" commands with the same key into one undo step (colour drags).
- Format version 2 adds layers. Version 1 files load through serde defaults; there is no per-version code path.
- Snapping is pure geometry in `cad-geometry::snap`: snap points per shape plus pairwise intersections of
  segment and arc primitives. Candidates are filtered by bounding box with a linear scan.
- 2D transforms are similarity matrices (`DAffine2`). A rectangle rotated off-axis becomes a closed polyline.
  Solids reject 2D transforms until Phase 3 gives them a full placement.

### Constraints
- `cad-constraints` holds the constraint types and the solver. It works on plain shapes and knows no document.
- Variables: Line `[a, b]`, Circle `[centre, r]`, Arc `[centre, r, start, sweep]`. Each constraint gives 1 or 2
  equations; the solver minimises them with Levenberg-Marquardt, which also keeps movement small when the sketch
  is under-constrained.
- After solving, the rank of the Jacobian gives the remaining degrees of freedom and the redundant equations.
  A set that does not converge is reported as unsatisfiable and nothing is changed.
- The document stores constraints. `History::execute` solves after the user's commands and records both in one
  undo step; if solving fails, the whole change is rolled back. Undo and redo replay stored commands and do not solve.
- An entity referenced by a constraint cannot be removed until its constraints are removed in the same transaction.

## 5. Rendering

- 2D viewport: egui painter, vector lines, top view of the XY plane.
- 3D viewport: wgpu inside an egui paint callback, depth buffer, one WGSL shader for lit triangles and unlit
  lines. Vertex buffers persist on the GPU and are replaced only when the scene revision changes.
- Instancing (Phase 7 batch A): every body's triangles and feature edges are uploaded once per body `Arc` (`scene_mesh`, `cad_renderer::MeshData`) and drawn per shown body or component with a model matrix and colour (`Instance`, shader `vs_instanced`); draws are grouped by mesh (`batch`). Gizmo, explode, motion and drag frames only rewrite the instance buffer. A body with a highlighted face, walls, entity primitives, caps and analysis overlays stay in the per-scene buffers. Frustum culling and LOD only after measurement (batch B).

## 6. Missing capabilities that must be built natively

Robust booleans, fillets, shelling and offsets; the sketch constraint solver; complete STEP and IGES; IFC;
FEA solvers; hidden-line removal. DWG has no acceptable pure-Rust path and stays a separate investigation.

## 7. Known Phase 1 limits

- Selection scans every entity. Acceptable for thousands of entities; an index comes with the Phase 2 benchmarks.
- No line types, line weights or per-entity colour yet (Phase 2).
- Units change only how lengths are displayed (dimensions, status bar). The model and the Properties fields stay in millimetres.
- Text width is estimated (0.6 x height per character) until real text shaping is added. The 3D view shows text
  and dimensions as outlines. Export is 2D only: solids are skipped, dimensions are exploded in DXF.
- Entities move in the 2D view, by numeric input, or (solids) with the translate gizmo of the 3D view.

## 8. MCP mode (test and automation interface)

`cad-app --mcp` runs the normal GUI and also serves the Model Context Protocol on stdin/stdout
(`crates/cad-app/src/mcp/`). A client can drive the real application without operating-system input.
`--background` opens the window off-screen with no taskbar button, so test runs do not cover the user's screen;
it still renders (a minimized window would not). The `tests/mcp_*.sh` scripts and `.mcp.json` pass it;
set `CAD_MCP_SHOW=1` to watch a run.

- `click`, `drag`, `scroll`, `key`, `type_text` inject events into egui (`App::raw_input_hook`). Positions are
  window pixels, or 2D world millimetres with `world: true`.
- `state` returns the tool, view, selection, cameras and the whole document as JSON.
- `screenshot` returns the application's own framebuffer as PNG.
- `new_project`, `open_project`, `save_project` replace the native file dialogs, which are disabled in this mode.

The protocol is hand-written JSON-RPC over newline-delimited JSON; no async runtime and no MCP library.
`.mcp.json` registers the debug build as the `projectcad` server. `tests/mcp_smoke.sh` is the end-to-end test.
The window must not be minimized, or requests time out after 30 s. In this mode the window ignores the real
mouse and keyboard: only MCP input reaches it, so a person moving the mouse over it cannot disturb a test.

Widgets are registered by name every frame (`crates/cad-app/src/widgets.rs`): buttons, labels and checkboxes by
their text, fields and combo boxes by their caption, repeated rows by occurrence index. `click_widget` and
`set_text` use these names and scroll a widget into view first; `widgets` lists them. Test scripts use names for
all UI clicks, so adding rows does not break them. Picks inside the 3D viewport still use pixel positions.

## 9. Solids, parameters and features (Phase 3)

- A 2D `Profile` (outer loop and holes of line and arc segments) is the input of every sweep.
- `cad-topology::Brep` is one closed shell: vertices, edges (line or arc), faces (analytic surface, outward flag,
  loops of coedges). `validate` checks manifoldness, loop closure and that vertices lie on their surfaces.
- `cad-modeler` builds B-Reps by `extrude` and `revolve` and tessellates them watertight: every edge is sampled
  once and shared; planar faces are triangulated, curved faces are four-sided grids projected onto their surface.
- Sweep, loft and the tapered extrude build their mesh directly: rings of profile samples joined by ruled quads, caps triangulated. A tapered extrude moves every loop to its material side by |distance| · tan(angle) with mitred vertices and refuses moves whose edges turn around or cross; straight walls keep a plane surface, walls of arcs are faceted; a zero taper uses the B-Rep extrude. A smooth loft runs every column of ring points through a uniform Catmull-Rom curve (mirrored end points, 8 rings per span).
- A `Body` is the tessellation plus, for every triangle, the analytic surface it lies on. Booleans combine bodies
  through `manifold-rust` and keep that mapping through its face ids. `TrimmedBody::from_body` rebuilds faces on planes and cylinders: one face per connected group of triangles, boundary loops walked on the mesh and split into the body edges, vertices snapped onto all their surfaces (1e-6). STEP writes such bodies as advanced B-Reps and falls back to a faceted B-Rep per body otherwise.
- `cad-params` evaluates named expressions with units; a bare number means millimetres or degrees by context.
- The document stores parameters and an ordered feature list. `Rebuilder` evaluates the list into the bodies. Each
  feature's change to the body list is cached under a key hashed from its resolved inputs and the versions of the
  bodies it reads (Phase 5 batch F; before, the previous feature's key), so unchanged features are not recomputed. A failed or suppressed feature leaves the body as it was.
- Entities used by a feature cannot be removed while the feature exists.
- Every entity belongs to a sketch; a sketch has a plane: a principal plane with an offset expression, or a plane
  on a picked face. The 2D view edits the active sketch only. Features take their plane from
  the sketch of their profile.
- The rebuild keeps a list of bodies. A body's id is the id of the feature that created it. `Add`, `Cut` and
  `Intersect` act on a target set (automatic, all bodies, or one body); `New` starts a body.
- Body edges are found on the mesh as boundaries between faces of different surfaces, after faces on the same
  surface are merged. A fillet or chamfer builds a tool solid along the edge (extruded for a straight edge,
  revolved for a circular rim) whose cross-section is the corner outside the fillet arc or the chamfer triangle,
  then subtracts it on a convex edge or adds it on a concave edge. The tool is tessellated finer than the body.
- Picks are references, not snapshots: a sketch on a face stores the plane, the picked point and the body; a fillet or chamfer edge stores a point and the keys of its two faces (outward plane normal or cylinder axis). The rebuild places each face sketch once, before the first feature that uses it (unused ones on the final bodies), on the planar face with the same normal under the picked point, nearest to it; edges are the nearest edge between faces with matching keys. Placed planes are returned in `RebuildResult::planes` and shown by the app.

## 10. Architecture (Phase 4)

- Architectural elements are entities with their own `Shape` variant (`Wall`, `Opening` for doors and windows, `Room`, `Slab`, `Roof`, `Stair`), so selection, transforms, undo, layers, snapping and the file format come from the entity code.
- A level is a sketch on XY with `level: Some(Level { height })`: name = storey name, offset expression = elevation, height = floor-to-floor height. Walls, rooms, floors, roofs and stairs live only on levels (`NotALevel`).
- Joins (`cad_arch::footprints`): ends within 0.001 mm meet; around the meeting point the ends are sorted by angle and each pair of neighbours meets where their facing faces cross. Three or more ends add the meeting point to each outline, so the hub is covered once. An end on another wall's baseline meets that wall's faces (T); crossing walls stay whole (X). Corners farther than 5 x the two thicknesses fall back to square ends.
- Plan (`cad_arch::plan`): every outline is filled; an outline edge is drawn only where no other outline covers it, which cleans L, T and X joins without a polygon boolean.
- Solids: the rebuild extrudes each outline from the level plane by the wall height into `RebuildResult::walls`. Walls are not features and are recomputed on every rebuild.
- Openings: `Shape::Opening` stores its host wall's entity id, the distance `at` along the baseline to its centre, width, height, sill, kind (Door/Window) and the door's hinge and swing sides, plus a copy of the host wall that `History::execute` refreshes after every edit (like linked dimensions), so bounds and picking need no lookup. The document refuses hosts that are not walls on the same level (`NotAHost`) and removing a wall that hosts openings (`HostInUse`); the app deletes them with it. A shortened wall slides its openings back inside without changing `at`.
- Cuts: the rebuild subtracts one box per opening from its wall solid (manifold difference), one thickness past each face, and past the floor, the top or a wall end the opening reaches, so no faces are coplanar. The plan clips each footprint into pieces beside the gaps before filling and edge cleaning.
- Rooms: `Shape::Room` stores a seed point, name and number; it is placed by one click inside an enclosed area. The seed carries the name through wall edits, which a purely computed room could not. `cad_arch::regions` chains the cleaned plan outline (without opening gaps) into loops; wall is on the left of every edge, so clockwise loops are enclosed areas. A room is the smallest one around its seed minus the free-standing wall groups inside it; net area and perimeter go into `RebuildResult::rooms`.
- Floors: `Shape::Slab` stores a closed outline and a thickness; the rebuild extrudes it from the thickness below the level plane up to it, into `RebuildResult::walls` with the wall solids. "Make floor" copies a room's current area or replaces a selected closed curve.
- Roofs: `Shape::Roof` stores the eave outline, kind (Flat, Shed, Gable, Hip), pitch, thickness at right angles to the slope and overhang. Every sloped plane rises at the same pitch from its eave line, so in plan a plane is the part of the eaves outline where its eave line is the nearest sloped one (`Roof::pieces`, half-plane clipping); on a convex outline that is the straight skeleton, so gable and hip need one. The solid (`cad_arch::roof_body`) is, per plane, a tall prism over its piece intersected with a sheet on the sloped plane; the planes only touch and are joined into one body without a union. The underside meets the eave line on top of the level.
- Stairs: `Shape::Stair` stores start, end of the run, width, height and riser count; the tread depth is the run over the treads (one fewer than the risers), so transforms work on the two points. The Stair tool takes the riser count from the storey height and the maximum riser. The solid (`cad_arch::stair_body`) is the stepped side profile, filled to the floor, extruded across the width.
- Multi-floor: the 3D view shows every level at its elevation; the plan can draw the level below or all other levels in grey under the active one. `Document::level_change` stores an edited level and gives a new storey height to the walls and stairs that still have the old one, in one undo step.
- BIM: the entity `meta` map is the property bag (`Pset_X.Prop` keys become IFC property sets). IFC class from the shape kind, storey from the level, quantities computed from the solids and GlobalIds derived at export. Doors and windows export as IfcDoor/IfcWindow (`cad_arch::ifc_class`) with an IfcOpeningElement that voids the host wall. Rooms export as IfcSpace (number as Name, name as LongName, NetFloorArea and NetPerimeter from the region) and floors as IfcSlab. Roofs export as IfcRoof and stairs as IfcStair. IFC4 export: Phase 7 batch C (§13).

## 11. Mechanical parts (Phase 5)

- Parts are features: `FeatureKind::Part { def, sketch, x, y, op, target }`. `PartDef` holds the generator parameters as expressions (teeth and turns are plain numbers, the thread size names a table row). The part sits on the sketch plane at (x, y) with its axis along the plane normal and combines with the bodies like an extrude (new body by default). `Document::part` evaluates it into a `cad_mech::Part`; the rebuild treats it as an `Inputs` with `Tool::Part`, so op, target, patterns and the cache (keyed by the evaluated part's Debug text) need no new code. A sketch used by a part cannot be removed.
- Gear: involute of the base circle, roll angle t: rb (cos t + t sin t, sin t - t cos t); tooth thickness pi m / 2 on the pitch circle (no shift, no backlash); 10 lines per flank, exact tip and root arcs; below the base circle the flank is radial. Extruded as a B-Rep.
- Shaft: the half section (steps and 45 degree end chamfers) turned by `cad_modeler::lathe`, which builds the mesh directly (regular polygons per ring, plane, cylinder and cone faces), because `revolve` needs a profile off the axis.
- Spring: a 24-gon wire section at right angles to the first segment of a helix polyline (48 segments per turn), swept with mitred corners; its volume is exactly the section area times the polyline length.
- Fasteners: hexagon head extruded and united with a shank that starts inside the head (no coplanar faces); nut = hexagon with a hole. Threads are cosmetic by default (nominal diameter); `Part::thread` names them. Modelled threads (batch E, `modelled` on bolt and nut): `cad_modeler::screw` builds a rod whose radius at angle θ and height z is R((z - Pθ/2π) mod P) from 48 profile samples per pitch, on rings of 48 vertices P/48 apart whose quads split along the helix diagonal, so every lattice vertex is an exact sample and the ISO 68-1 corners (multiples of P/16) stay sharp in the geometry. Bolt = head ∪ rod (basic profile less 0.04 mm) from -length to k/2; nut = prism − rod (basic profile) from -P to m + P. The phase is anchored at the part's plane origin and x axis, so a nut fits only a whole number of pitches from the bearing face (or turned by 360° x offset / P); the interference check reports a mismatch as flank overlap.
- Bearings (batch E): `BEARINGS` holds ISO 15 boundary dimensions; ball diameter 0.3 (D - d), pitch circle (D + d)/2, z = floor(π dm / 1.6 Dw) balls, groove radius 0.52 Dw about the ball centre circle, shoulders at dm/2 ∓ 0.3 Dw. Rings are revolved sections (plane, cylinder, torus faces); one lathe-turned ball relabelled as a single sphere face is copied z times with `Body::transformed`; the disjoint pieces are united into one body.
- BOM data is derived: `Part::designation` and `Part::thread` come from the evaluated parameters; the part name is the feature name.
- Components (batch B): `Component { id, name, body, at, angles, meta }` in `Document::components` places one body (the id of the feature that made it) with p' = Rz Ry Rx p + at; all six values are expressions. `RebuildResult::components` holds the placed solids (`Body::transformed`), recomputed on every rebuild while the features stay cached. A body with components stays in `RebuildResult::bodies` (sketches on its faces, targets, patterns and masses use it) but is drawn and picked only through its components. Removing its feature is refused (`BodyInUse`). The translate gizmo moves the selected component and writes plain millimetres into `at`. Its rings (Phase 7 batch D) turn it about its bounding-box centre (`Document::component_turned`: `at` in mm, `angles` read back from the turned matrix in Rz Ry Rx order, degrees). `grounded` (batch C) keeps a component from being a joint child and from the gizmo.
- Bill of materials: `Document::bom` groups components by designation (by body when there is none), material and part number (component meta), numbers the rows in the order of their first component and computes the mass per piece from the body volume and `cad_mech::density`. `bom_csv` writes it with a UTF-8 byte order mark; File > Export BOM CSV... and `export_project` with `.csv` use it; the MCP `state` lists `components` and `bom`.
- Joints (batch C): `Joint { id, kind, parent, child, parent_frame, child_frame, value }` in `Document::joints`. A frame is an origin (length expressions) and an axis (numbers) in the component's own coordinates; `cad_mech::frame` derives X from the axis (world X minus its part along the axis, world Y near X). `Document::placements` walks up from each component to its root (memoised): a root uses its own `at`/`angles`, a child gets parent placement x `cad_mech::mate` = parent frame x motion x flip x child frame⁻¹ (motion: turn about Z, move along Z or nothing; flip: half a turn about X, so the axes point at each other like touching faces' normals). Checks on every add, edit and load: both components exist, the child is not grounded, has one parent and is no ancestor of the parent. Joint errors fail the child's subtree. `cad_mech::face_frame` gives a plane face's centroid and outward normal or a cylinder's axis; the Assembly tab writes it into a frame as numbers plus a face reference that `placements` resolves on every rebuild (batch F), so the frame follows the face.
- Exploded views: `Document::explode` steps (component, direction, distance), replaced as a whole by `SetExplode`; `explode_offsets(factor)` runs the steps one after another. The factor, toggle and trail lines are app state; the offsets move the drawn solids and the picking ray only.
- Export: STL/OBJ/STEP write the shown bodies plus the placed components; `to_obj`/`to_step` take a name per solid.
- Interference (batch D): `cad_mech::check` takes the placed solids with ids, converts each to a parry mesh once and visits every pair whose bounding boxes are within the clearance limit. Per pair the surface distance comes first (below); the manifold boolean runs only for pairs whose surfaces touch (within `CONTACT_GAP`) or whose boxes nest, because apart surfaces with no nested box cannot share a volume. `overlap` intersects a pair with the manifold boolean (an empty or not closed result means no common volume): a common solid is interference with its exact volume unless the volume is at most 1e-6 mm³ or its mean thickness 2V/A at most 0.04 mm (twice `BODY_TOLERANCE`), which is contact, like solids whose surfaces are within 1e-6 mm; faceted copies of one cylinder (a cosmetic-thread bolt in its nut) are therefore contact at any rotation. `clearance` converts both meshes to parry `TriMesh`es and asks `query::distance` first (best-first, cheap); beyond the limit there is no clearance, at 0 the surfaces intersect. Otherwise the closest points come from `query::contact` with a prediction just above that distance, because parry 0.19's mesh-mesh `query::closest_points` panics when a visited triangle has nothing within the margin (surfaces only; a solid inside another is caught by `overlap` first). `Document::check(result, limit)` runs it on `RebuildResult::components` (assembled placements). The Assembly tab runs it on demand; the result is app state keyed by the document revision, drawn while not exploded (common solids red, their components as edges only, clearance lines green) and listed in the MCP `state` as `check`.
- Dependency graph (batch F): the rebuild walks the features in list order, but a feature's key hashes its own evaluated inputs with the versions of the bodies it reads (`Step::reads`: none for `New`, the targets for `Add`/`Cut`/`Intersect`, the root's reads for a pattern, every body for fillet, chamfer, shell and mirror of all bodies, its body for a draft); a body's version is the key of the feature that last wrote it. The cache keeps each feature's `Delta` (bodies put, ids removed) and applies it to the current list on a hit. `RebuildResult::depends` holds the graph (last writers of the bodies read, of the body under a face sketch, and the pattern source); the feature editor shows it as "Uses: ...", the MCP `state` as `depends` with `recomputed`.
- Face references (batch F): `FaceRef { key, at }`; `find_face` takes the planar face with the same outward normal under `at` along the normal (nearest along it), or the cylinder with the same axis whose area centroid is nearest. `FaceRef::of` uses the centroid of the face's largest triangle, which lies on the face even when it is not convex.
- Draft (batch F): `FeatureKind::Draft { body, faces, sketch, angle }`; the neutral plane is the sketch's plane, the pull direction its normal. `cad_modeler::draft_face` moves the face's vertices by -h tan(angle) along its outward normal (h above the neutral plane) and sets the plane n cos(angle) + pull sin(angle) through the hinge line. Faces sharing a moving vertex must be planes containing n, so they stay flat and no boolean is needed; others are refused, and so are flipped triangles. All faces of one draft are found on the input body first.

## 12. Engineering analysis (Phase 6)

- Accuracy labels: `cad_analysis::Accuracy` = `Exact` | `Approximate(reason)` | `Validated(case)`, printed as "exact", "approximate (tessellation)", "validated against cantilever beam". Every analysis result carries one; only the analytic benchmark cases (batch F) are ever "validated", and nothing is called certified.
- Mass properties (batch A): `MassProps::of(mesh, density)` sums signed tetrahedra from a reference point r (the first vertex): d = a · (b × c), V = Σ d/6, first moment Σ d (a+b+c)/24, second moment C = Σ d/120 (a aᵀ + b bᵀ + c cᵀ + s sᵀ), s = a+b+c; centre c = first moment / V, C_c = C − V c cᵀ, inertia I = ρ (tr(C_c) 𝟙 − C_c) with ρ = density/1000 g/mm³ (density in g/cm³, results in mm, g, g·mm²). Exact for the mesh: `Accuracy::of_body` says exact when every face is a plane, approximate (tessellation) otherwise. `inertia_at` and `combine` use the parallel axis theorem; `principal` runs cyclic Jacobi rotations on the 3 x 3 tensor (ascending moments, axes signed so their largest component is positive, the third the cross product of the first two).
- `Document::mass(result)`: bodies at an assumed 1 g/cm³, placed components at the density of their "material" metadata (unknown: 1 g/cm³, flagged `assumed`), the assembly total about its centre of mass (exact only when every component is). The app computes it once per rebuild result (`CadApp::mass`); the Model and Assembly tabs show it, the 3D view paints a centre of mass symbol on top of the scene (assembly, else all bodies; hidden while exploded), the MCP `state` lists it as `mass`.
- Joint limits and motion studies (batch B): `Joint::min`/`max` (optional expressions, file format 24) are checked by `Document::check_limits` inside the joint walk (`mate`), so a value outside fails the child's placement; limits refuse, never clamp. `Document::drive(result, study)` checks start and end against the limits, then for each of the steps + 1 samples (at most 361; the last is exactly the end value) runs the walk with the driven joint's value replaced (`placements_driven`) and records, for the joint's child and every component placed through it, the motion from its rebuilt solid (P_k · P_rebuilt⁻¹) and the traced point. `first_collision` moves those solids per sample and runs `cad_mech::overlap` against the components that do not move (moving pairs keep their relative pose; contact does not count), stopping at the first interference. Positions are labelled exact, collision results "approximate (sampled at the steps)". The app runs both on demand on the analysis worker (§13), keeps the result for the document revision it ran on (`CadApp::motion_result`), draws the shown sample by transforming the moving components' meshes (display only), paints the interference region at the colliding sample, and writes CSV with `Document::motion_csv`.
- Closed loops and dragging (batch C): `Joint::closes_loop` (not walked; `parent_joint` and the tree checks skip it) and `Joint::free` (the value expression is a start guess), file format 25. `Document::solve_joints` runs `cad_constraints::least_squares`, the Levenberg-Marquardt loop moved out of the sketch solver unchanged, over the free values: per closing joint the offset m = Fp⁻¹ · Tp⁻¹ · Tc · mate(I, I, Fc)⁻¹, which is the joint's own motion exactly when the loop closes, gives the translation (a slider frees Z), the turned Z axis minus Z (a revolute frees the turn) and for slider and fixed the turned X axis minus X; derivatives by central differences over the walk (without limits). Unknowns minus the Jacobian's rank left over is "under-constrained", a residual with no unknown "over-constrained", no convergence "does not close"; redundant consistent equations (every planar loop) are fine. The walk afterwards checks limits, so a solved value outside them is refused like a typed one. `placements_driven` solves before walking and fails the loop's components on an error; the rebuild keeps the solved values (`RebuildResult::joint_values`), and `drive` and `pose` warm-start from the previous solution so a linkage stays on its branch. Loop positions are labelled "approximate (loop closed to 1e-9 mm)"; the four-bar test against `cad_analysis::four_bar_rocker` (Freudenstein) is the validated case. The joint editor's "Drag" slider shows `Document::pose` in 3D while dragging and writes the value and the free joints' solved values in one undo step on release.
- Tetrahedral mesher (batch D): `cad_analysis::tet_mesh(surface, h)`. Grid over the surface's box with ceil(L/h − 1e-9) cells per axis (so the grid ends on the box and boxes mesh exactly), each cell cut into the 6 Kuhn tetrahedra (paths from corner 0 to corner 7, ordered for positive volume; every cell face is cut along its lowest-to-highest diagonal, so neighbours conform). A candidate is kept when its centroid is inside: the centroids of one Kuhn type lie on rows along x, so one `Bvh::hits` ray per row and type gives the parity for the whole row; rows are moved by (√2, √3) · 1e-3 of a cell so they miss edges of faces on grid lines, and hits at one edge or vertex count once when their triangles face the same way along x, never when they disagree (grazing). Centroids rather than grid points, because grid points lie on aligned faces. Boundary corner nodes (on faces used by one element) move to their nearest surface point (`Bvh::nearest`), trying 1, 1/2, 1/4 of the way, accepted only when every element of the node keeps a positive volume and a radius ratio ≥ 0.15; two passes; the rest are counted as `unsnapped`. So no element is inverted, and the worst radius ratio is 0.15 unless the grid cells themselves are worse. Mid-side nodes are the midpoints of the snapped corners (C3D10 / VTK_QUADRATIC_TETRA order 01, 12, 20, 03, 13, 23). A Python prototype chose the quality guard over a 10 % volume guard (smallest radius ratio 0.055 against 0.15 at the same < 1 % volume error on a cylinder) and showed interior smoothing does not lift the worst elements. `Document::mesh_body` meshes a body of the rebuild result (element size a length expression; at most 50 000 cells), `MeshReport` compares the mesh volume with the body's and is labelled "approximate (mesh)"; `Document::face_nodes` gives the nodes within h/4 of a face found from a `FaceRef`, for E's supports and loads. The Model tab meshes on demand on the UI thread (dropped by any edit, like the interference check) and draws the boundary faces with edges or shrunken elements in place of the body; `fea_mesh` in the MCP `state`.
- Static FEA (batch E): `cad_analysis::fea`. Straight 10-node tetrahedra; shape function derivatives in volume coordinates (corners Lᵢ(2Lᵢ − 1), mid-sides 4 La Lb), J = Σ xₙ ⊗ dNₙ, ∇N = J⁻ᵀ dN; element stiffness by the 4-point Gauss rule (exact for the degree-2 integrand), written per node pair as λ g_a g_bᵀ + μ g_b g_aᵀ + μ (g_a · g_b) 𝟙 (the isotropic Bᵀ D B; a unit test compares it with an explicit B and D and finds exactly six zero eigenvalues). Assembly goes straight into the lower triangle of a CSC matrix over the free DOFs (pattern from node adjacency, values located by binary search), so memory follows the non-zeros instead of 465 triplets per element; fixed DOFs are eliminated (u = 0); faer sparse Cholesky solves, and a failed factorisation or an out-of-balance above 1e-6 is reported as "the supports do not hold the body". Loads: uniform traction on straight 6-node boundary triangles gives the corners 0 and each mid-side node A/3; a force is spread as F / face area, a pressure as −p n; gravity gives corners −W/20 and mid-sides W/5 per element. Stresses are evaluated at each element's nodes (exact for the linear stress of a straight TET10), averaged as tensors, then von Mises. Reactions = internal minus external forces over the fixed nodes; |reaction + applied| / Σ |load| is reported as the out-of-balance. A bar with ν = 0 is reproduced to round-off (unit test), since its exact solution is linear. `Document::run_study` meshes the body, finds the fixed and loaded nodes with `face_nodes` and the loaded boundary triangles as those with all three corners on the face; studies are stored (`Command::SetStudies`, file format 26), results never are. The Model tab's "Static study" section runs on the analysis worker (§13) (at most 30 000 unknowns; times shown) and draws the deformed boundary coloured per corner node with a legend; `fea_study` in the MCP `state`. All results are "approximate (FEA, linear elastic, mesh h=…)"; F validates against analytic benchmarks.
- Validation and safety factor (batch F): `cad_document::validation`. `benchmarks()` builds each case through commands (sketch rectangle or circle, extrude; components and joints for the four-bar) and runs the code the app runs (`run_study`, `mass`, `drive`), so it checks what users run. A `Benchmark` row holds case, quantity, formula, reference, result, tolerance (relative; absolute in degrees for the four-bar, whose reference is 0), the mesh and the computation's own label; `accuracy()` is `Validated(case)` only when |error| ≤ tolerance, which is the only place that label is produced. Cases: steel cantilever 100 x 10 x 10 mm at h = 10, 5, 2.5 mm, tip deflection of the end's centre node against Timoshenko (−2.44 %, −1.11 %, −0.81 %) and von Mises at the top node of mid-span against M c / I (+2.48 %, +0.87 %, +0.21 %), both within 3 % and falling with h (the clamped root's corner singularity is not compared); bar in tension with ν = 0, exact to round-off; box mass properties exact; cylinder volume −0.26 % and inertia −0.38 %, −0.53 % on 196 facets; four-bar within 1e-6°. The suite runs in under a second in debug builds, so `cargo test` runs it whole; `cargo run --release -p cad-bench -- validate` writes docs/VALIDATION.md; the Model tab's "Validation report" runs it on demand; `validation` in the MCP `state`. Matching a user's study against a case is not attempted, so studies stay "approximate". `Material::yield_strength` and `Study::yield_strength` (an expression; empty = not given; file format 27); `StudyReport::safety_factor` = yield strength / largest nodal von Mises stress.

## 13. Optimization and production (Phase 7)
- Measured first: an optimisation batch opens with a `cad-bench` case (or, for code that lives only in `cad-app`, the in-app timer `perf` read through MCP), records the numbers before any change in `docs/BENCHMARKS.md`, and closes with the after numbers and its threshold; a missed threshold stops the batch.
- Component placement (batch A): `Rebuilder` keeps per component (source body `Arc`, placement, placed solid) and reuses the solid while both are unchanged, so unchanged components keep their `Arc` (BVH and GPU mesh caches hit); the rest are copied in parallel with rayon. `RebuildResult::placements` gives the placement of every placed component for instanced drawing.
- Instanced drawing (batch A): see §5. Numbers: docs/BENCHMARKS.md, "Phase 7 batch A".
- Analyses off the UI thread (batch B): `analysis_worker::Jobs` runs one job at a time on a thread of its own (a static study, motion study, interference check or the validation benchmarks); the job owns clones of the document and of the rebuild result (`Arc`s) and carries the revision it read. Each frame the app drops a job whose revision is no longer the document's (cancel on edit; also on new/open, "Cancel job" and a newer job), then hands a finished one to its panel's `finish`, which stores it under that revision as before, so a stale result is never shown. A cancelled thread runs on to its end (the mesher, solver and booleans have no stop points; bounded by `MAX_CELLS`, `MAX_DOFS`, `MAX_STEPS`) and its output is dropped. The status bar shows the job, its elapsed seconds and "Cancel job". The MCP bridge waits for `CadApp::idle` (rebuild current and no job) before replying to input and before answering `state`, `screenshot` and exports, as it waited for rebuilds; `jobs` in the state counts finished and cancelled jobs. The analysis mesh stays on the UI thread (3.7 ms).
- Measured and dropped in batch B: see docs/ROADMAP.md Phase 7 "Won't do" and docs/BENCHMARKS.md "Phase 7 batch B".
- Exchange formats (batch C): `cad_import_export::Scene` (each solid once, placed by items) feeds glTF (.glb: node 0 turns Z up into Y up, positions and translations in metres, one vertex per corner, one grey material) and 3MF (stored zip written by hand with CRC-32; objects and build items with row-vector transforms, mm). IFC4 (`to_ifc`) reads the levels and the rebuild's wall, slab, roof and stair solids and room areas: storeys placed at their elevation under building and site, elements relative to their storey; walls, openings (`cad_arch::opening_box`), doors, windows, slabs and spaces as IfcExtrudedAreaSolid, roofs and stairs as IfcFacetedBrep; `Pset_X.Prop` metadata as property sets; GlobalIds from FNV-1a of document name and kind plus the id. STL and OBJ import become `FeatureKind::Mesh` (f32 points and index triangles in the project file, version 28), rebuilt by `Body::from_mesh` (closed and consistently oriented, Faceted faces split at 30 degree creases). STEP writes cones and spheres exactly: `TrimmedBody` fits circles on their edges itself, so `Body::edges` and the blends are unchanged.
- Production UI (batch D): settings (`cad-app` module `settings`: theme, accent, layout) are a JSON file of the app, not of the project: `CAD_SETTINGS`, else `%APPDATA%\ProjectCAD\settings.json` or `~/.config/projectcad/settings.json`; MCP runs read only `CAD_SETTINGS`, so scripts start from the defaults. The Sketch, Model and Assembly panels dock to Left, Right or Bottom slots drawn with egui's `Panel` (no `egui_dock`: no release for egui 0.37 in the registry, and its dock area would replace the central view); the default layout is the old 240-point right panel. Command search (`palette`): Ctrl+K snapshots the named widgets of the last frame (the registry MCP reads), ranks them by a greedy fuzzy score and clicks the chosen one through egui events, scrolling it into view first. Gizmo: rings of radius 0.12 x the camera distance around the arrows of a free component; a ring drag measures the angle where the ray meets the ring plane, unwrapped per frame, snapped to 15 degrees with Shift. A component on a revolute or slider joint shows one handle about or along `Document::joint_axis`; its drag sets value = start value + angle or distance, shown with `Document::pose` and written with the free joints' solved values in one undo step (`assembly_joints::commit_joint_value`). MCP `state` adds `settings`, `palette`, `gizmo_rings` and `gizmo_joint`.
- Plugin API (batch E): plugins are separate programs speaking the app's MCP (no ABI, no unsafe). `Command` derives serde (externally tagged JSON; its payloads are the project file's types, so the schema follows `FORMAT_VERSION`; commands are never saved, so the format stays 28). MCP `apply_commands` deserialises each command strictly (index in the error), takes at most 10 000, and runs them through `History::execute`: one undo step, rolled back whole on any error; the reply carries the feature count, `format_version`, `Document::next_ids` and the inverse step (`History::last_undo`); commands carry their own ids, numbered from `next`. Plugins menu (`cad-app` module `plugins`): manifests `plugins/<file>.json` (name, command, args, version) beside the settings file, read at startup and on "Reload plugins"; a click starts the program directly (no shell, `CAD_PLUGIN=1`, no console window) and `mcp::spawn_plugin` serves MCP over its pipes with the document tools only (`tools::plugin_allowed`); the MCP loop `serve` is generic over its streams; the stdio bridge holds state, screenshot and export replies while a plugin runs, a plugin's own bridge never waits. `cad-plugin-api`: `Client::spawn` (`cad-app --mcp --background`) or `Client::stdio`, one typed method per tool, `PluginError`, version check at connect; example `bolt_circle`. Security: plugins run as the user; never started by the app or from a project. MCP `state` adds `plugins`.
- Documentation and release (batch F): docs/USER_GUIDE.md by task, screenshots only from `tests/mcp_docs_shots.sh` (`--background`; writes to `target/docs_shots` unless `SHOTS=docs/images`), README, CHANGELOG.md; version 0.2.0 (workspace version and every path dependency's `version`); CI adds `cargo clippy --workspace --all-targets -- -D warnings`; `release.yml` builds the archives when the user pushes tag `v0.2.0`. No code or file-format change.
- Phase plan: docs/ROADMAP.md; everything not done, in one list: its "Beyond the roadmap" section.
